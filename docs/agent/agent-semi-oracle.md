# Semi-oracle RuleSets

The semi-oracle is a host-side verifier for small, explicitly bounded rule
families. It is not an LLM judge and the model cannot declare its own answer
correct. V1 implements `placement_game` (small two-player placement games) and
`linear_algebra` (one-variable linear equations over exact rational numbers).
Chess, navigation, incomplete-information games, nonlinear algebra and
arbitrary executable user rules are unsupported.

## Tool boundary

The model-facing native tool family is `semi-oracle`. Select it when the user
has supplied rules for a small two-player placement game or a one-variable
linear-equation task and wants a move/step checked. For a game with no stated
rules, ask for the rules first; do not treat the oracle as a general game
solver or a general-purpose algebra tool.

- `oracle.ruleset.define` is for the initial explicit rules or a user
  correction, once per RuleSet revision—not for every move. It accepts a
  bounded flat `field: value` RuleSpec DSL (an exact `open!` header is
  optional). The host assigns the opaque RuleSet ID, revision, scope and
  assertion provenance; the DSL cannot supply these values.
- `oracle.action.verify` accepts the domain-specific action DSL. For algebra,
  the model may provide only the changed equation side(s); omitted sides are
  copied from the host's current state. The host rejects a no-op rewrite. The host
  supplies the active session binding, state, search level, budget and any
  guidance. The model only proposes the action/rewrite.

The daemon binds the regular tool adapter to a host-owned
`common_semi_oracle_tool_service`. It opens SemiOracle on the configured
adaptation backend/path (Cozo when configured; in-memory if no path is
configured), rather than creating a second database. It stores one typed,
host-owned state per session and RuleSet revision. `oracle.action.verify`
receives only the proposed action; a proved transition advances that stored
state, while `VIOLATED`/`UNKNOWN` leaves it unchanged. Re-defining a RuleSet
creates a revision with fresh domain state.

For `placement_game`, the host initializes the empty board from the validated
RuleSet. For `linear_algebra`, the daemon initializes the first state only from
a supported equation explicitly present in the user's turn; later rewrites use
the persisted equation state. The model never supplies either board or equation
state in an action call. A request without a supported initial equation gets a
targeted state-required error rather than silently accepting an invented state.

RuleSet IDs are generated by the host. A session binds to an immutable
revision. Re-defining/correcting rules keeps the ID and creates a new revision
with a parent link. A RuleSet starts session-scoped; promotion is an explicit
host call. Promotion changes visibility, not semantic fingerprint or
provenance, and does not upgrade inferred assertions.

## Authority and FlyDelta

Rule assertions retain `declared`, `verified` or `inferred` provenance. A
deterministic evaluator can still be applying an inferred or incorrect rule;
therefore evaluator determinism alone is not sufficient for training credit.
Only a same-revision contrast with a host-proved `VIOLATED` baseline and
`SATISFIED` candidate, no inferred assertions, and non-empty proof/counterexample
can be converted by `common_semi_oracle_make_teaching_relation` into the
existing `user_taught_concept` teaching relation. The relation includes the
RuleSet semantic revision and action-contract fingerprint in its behavioral
identity. Revision changes must not reuse prior evidence without an explicit
compatibility check. `UNKNOWN`, exhausted budgets and inferred-only rule sets
remain diagnostic; they are not FlyDelta or training admission.

The bridge API creates the existing teaching-relation type; it does not
introduce a second capture/training store. The daemon does not yet provide a
SemiOracle-specific `user_taught_concept_relation_provider`, so this relation
is not currently constructed from live game turns or sent to FlyDelta capture.
The normal capture, contrast and admission components remain the intended
downstream path once the host can resolve real execution/capture references.

For strategic placement behavior, a legal-but-worse action is not an Oracle
violation. The host-only `rank_placements` service runs memoized minimax for
each legal action from the current player's perspective and persists the full
bounded result through the existing evaluation store. A FlyDelta preference
relation is eligible only when two distinct actions in the same state and
revision have complete, persisted proofs and the preferred outcome is strictly
better (`loss < draw < win`). This is a preference comparison, not a false
`VIOLATED` verdict. The relation remains session-scoped; it does not promote
the RuleSet or create a FlyDelta overlay by itself. The host still has to
present it through the existing `user_taught_concept_relation_provider` and
let production capture and admission gates run; the semi-oracle smoke does not
claim to exercise those activation steps.

The daemon now attaches a `semi_oracle_preference` learning signal only when a
declared placement-game RuleSet has a complete minimax ranking and proves the
model's observed legal move strictly worse than another legal move. This is
stored as host-verified learning evidence with the tool observation. It is not
yet marked candidate-ready and does not itself enqueue FlyDelta capture: the
observed/preferred/control execution relation and activation capture still need
to pass through the ordinary relation provider and capture pipeline. Thus this
wiring is evidence ingress, not proof that nearline FlyDelta changes the
model's move selection.

## Offline SFT and leakage-safe splits

The same verified minimax action can become an SFT demonstration through
`common_semi_oracle_make_sft_candidate`, then enters the existing shared
learning corpus and trainer-job path. It is tagged
`host_verified_demonstration`, carries the persisted evaluation/action proof
reference, and requires a caller-provided redaction attestation and explicit
curator approval before corpus admission. This provenance path never invents
model occurrences or recoveries; those remain zero. In contrast,
`observed_model_behavior` candidates continue to require their normal
occurrence, verified-recovery and approval thresholds.

This admission is explicitly offline SFT only. The shared corpus builder opts
in to host-verified demonstrations for the SFT objective; DPO still requires
real chosen/rejected pairs, and default candidate qualification (including the
nearline auto-training trigger) rejects solver demonstrations. A solver proof
therefore cannot silently count as an observed model recovery or start online
training.

Position examples carry a `split_group_key` based on a canonical board under
the RuleSet's symmetry group (all eight symmetries for square boards and
dimension-preserving reflections for rectangular boards). The shared corpus
builder splits by this key when present, so rotated/reflected versions of one
position cannot straddle train, validation and test. RuleSet revision and
side-to-move are included in the group identity.

The current implementation exposes two distinct inputs for later comparison,
not two completed adaptation paths:

1. Runtime records host-verified evidence when minimax proves an observed
   model move strictly worse. It is not candidate-ready: matched preferred and
   control executions plus activation captures are not yet wired into the
   relation provider/capture pipeline.
2. Offline SFT can use curated solver demonstrations projected through the
   shared candidate, corpus, redaction and trainer-job contracts. This is a
   separate offline path and does not establish a FlyDelta effect.

The Qwen model smoke reports the observed move against minimax. When the
observed move is strictly worse, it also projects that same-state pair into
the shared offline DPO corpus and creates an ordinary DPO trainer job. The
smoke does not launch training, capture FlyDelta activations, activate or
claim an adapter. Adapter comparison remains a later operation over an
approved corpus and the same held-out symmetry groups. The smoke's DPO
projection is only corpus/trainer-job construction; it is not an adapter
training result.

## Strict minimax DPO pairs

For placement games, `common_semi_oracle_make_dpo_candidate` can project two
actions from the same persisted, complete minimax ranking into one ordinary
`common_training_candidate`. The chosen action must have a strictly better
minimax outcome than the rejected action. Equal-value moves are deliberately
not ordered. Both action proofs, the evaluation reference, RuleSet revision,
action-contract fingerprint and symmetry group are retained; the prompt and
redaction attestation still come from the host/curator. Inferred RuleSets are
rejected for both SFT and DPO admission.

The shared corpus builder accepts host-verified examples for SFT as before.
For DPO, host-verified pairs are rejected by default and require the explicit
offline-only `common_learning_corpus_policy::allow_host_verified_dpo_pairs`
opt-in. This flag only affects corpus construction; it does not relax nearline
candidate qualification or create observed model behavior. The DPO row uses
the chosen and rejected DSL actions from the pair, and its strict contrast
reference points back to the persisted minimax evaluation. This supports
curated corpus generation, not automatic adapter training, activation or
promotion.

The persisted preference-relation bridge is exposed by
`common_semi_oracle_tool_service::make_preference_relation`. A host may call it
from the existing `user_taught_concept_relation_provider` after it has an
observed model action and host-owned references for the preferred and matched
control capture contexts. The method re-loads the persisted ranking and checks
that both actions are in it before using the existing FlyDelta relation
contract. It does not fabricate execution references or invoke capture itself;
the ordinary relation observer, concept-capture worker, synthesis and search
remain responsible for those downstream stages. The existing direct SemiOracle
model smoke still tests rule/action inference only; it is not evidence of a
full SemiOracle-to-FlyDelta model E2E.

## Search levels

- `local`: verify one proposed placement or equation rewrite.
- `bounded`: placement games use deterministic minimax bounded by host depth
  and expansion limits. Linear equations use exact rational normalization to
  prove the unique solution; this is currently a bounded closed-form solver,
  not a general rewrite-tree search.
- `guided`: for placement games, host guidance changes move ordering only. The
  same legal transition model, search limits and verdict rules apply. Guidance
  is not a source of truth. V1 does not use a learned value model or MCTS.

Proof/counterexample data is emitted only for established results. A cutoff,
unsupported expression or invalid game state returns `UNKNOWN` (invalid DSL
shape is a tool validation failure).

## V1 constraints

`placement_game` supports boards up to 8×8, two alternating players, placing a
mark into an empty cell, a configurable contiguous win length and draw on a
full non-winning board. The first declared player starts. State validation
checks turn/count consistency and rejects simultaneous winners.

`linear_algebra` supports only variable `x`, integer constants, parentheses,
addition/subtraction, multiplication where at most one factor contains `x`,
and division by a non-zero rational scalar. It checks equivalence by exact
rational normalization. Unsupported/nonlinear expressions and arithmetic
overflow return `UNKNOWN`.

## Validation and model smoke

Model-free tests cover RuleSpec parsing, domain validation, legal/illegal game
transitions, per-action minimax ranking and budget cutoffs, symmetry grouping,
proof-verified preference relations, SFT provenance/admission, symmetry-safe
corpus splitting, exact algebra equivalence, authority gating, revision
identity, tool registration and Cozo evaluation roundtrip. Run:

```sh
ctest --test-dir build-agent-vulkan-cozo --output-on-failure -R 'test-agent-semi-oracle'
```

The opt-in Qwen Instruct smoke preserves full prompt and model output, runs the
registered native tool wrapper, and checks tic-tac-toe plus algebra through the
same active-state transition service. Its fixture seeds domain state as a host
operation; the generated action contains no state:

```sh
LLAMA_AGENT_MODEL=/path/to/Qwen-Instruct.gguf bash scripts/test-agent-semi-oracle-model-smoke.sh
```

Set `LLAMA_AGENT_MODEL` and adjust `LLAMA_AGENT_TIMEOUT_SECONDS` when needed. The model
loader uses parameter fitting (`fit_params=true`) and the default requested
GPU layer count is 99, so the configured auto-fit path is retained.

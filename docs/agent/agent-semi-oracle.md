# Semi-oracle RuleSets

The semi-oracle is a host-side verifier for small, explicitly bounded rule
families. It is not an LLM judge and the model cannot declare its own answer
correct. It implements `placement_game` (small two-player placement games),
`linear_algebra` (one-variable linear equations over exact rational numbers),
and `target_hunt` (bounded, fully observed orthogonal mazes).
Chess, arbitrary navigation, incomplete-information games, nonlinear algebra and
arbitrary executable user rules are unsupported.

## Tool boundary

The model-facing native tool family is `semi-oracle`. Select it when the user
has supplied rules for a small two-player placement game, a one-variable
linear-equation task or Target Hunt and wants a move/step checked. For a game with no stated
rules, ask for the rules first; do not treat the oracle as a general game
solver or a general-purpose algebra tool.

- `oracle.ruleset.define` is for the initial explicit rules or a user
  correction, once per RuleSet revision—not for every move. It accepts a
  bounded flat `field: value` RuleSpec DSL (an exact `open!` header is
  optional). The host assigns the opaque RuleSet ID, revision, scope and
  assertion provenance; the DSL cannot supply these values.
- `oracle.action.verify` accepts the domain-specific action DSL. For algebra,
  the model may provide only the changed equation side(s); omitted sides are
  copied from the host's current state. The host rejects a no-op rewrite. The host
  supplies the active session binding, state, search level, budget and any
  guidance. The model only proposes the action/rewrite.
- `oracle.goal.search` is an argument-free host operation for declared algebra
  and Target Hunt sessions. It searches for `x = rational` or a legal grid
  path, using host-owned state, goal, budget and guidance. Exact A* is the
  default and proves a shortest path for the admissible Target Hunt heuristic;
  opt-in Focal A* reports its quality bound separately. It preserves position
  and equation state. `oracle.problem.define` admits Target Hunt maps explicitly.

The daemon binds the regular tool adapter to a host-owned
`common_semi_oracle_tool_service`. It opens SemiOracle on the configured
adaptation backend/path (Cozo when configured; in-memory if no path is
configured), rather than creating a second database. It stores one typed,
host-owned state per session and RuleSet revision. `oracle.action.verify`
receives only the proposed action; a proved transition advances that stored
state, while `VIOLATED`/`UNKNOWN` leaves it unchanged. Re-defining a RuleSet
creates a revision with fresh domain state.

For `placement_game`, the host initializes the empty board from the validated
RuleSet. For `linear_algebra`, the daemon initializes the first state only from
a supported equation explicitly present in the user's turn; later rewrites use
the persisted equation state. The model never supplies either board or equation
state in an action call. A request without a supported initial equation gets a
targeted state-required error rather than silently accepting an invented state.

## Shared bounded search and algebra A*

SemiOracle exposes a domain-neutral deterministic search contract consisting
of an initial state, verified successor transitions, a goal predicate, edge
costs, an optional heuristic and bounded expansion/depth limits. It is a
search interface, not a universal domain evaluator: each adapter owns the
semantics and must verify every transition. The reusable A* engine owns only
frontier ordering, duplicate suppression, path reconstruction and budgets.

The linear-algebra adapter currently generates a bounded V1 rewrite graph:
exact simplification/distribution, moving variable terms, moving constants,
and division by a non-zero rational coefficient. Every edge is checked by the
same exact rational equivalence predicate as `oracle.action.verify`. The goal
is a normalized `x = rational` equation. A zero admissible heuristic gives a
shortest path in this generated transition graph; the proof records each
state/action, RuleSet and action-contract fingerprints, cost, expansion count
and evaluator revision. If a bound prevents proving the goal, the result is
`UNKNOWN` rather than a guessed answer.

Placement games remain on minimax, not A*: choosing a move changes an
adversarial state whose value depends on both players' replies. The common
search contract can support other deterministic path-planning domains, while
minimax remains the correct solver for this game family. Level-2 guidance may
reorder successors, but cannot alter transition validation or the goal test.

RuleSet IDs are generated by the host. A session binds to an immutable
revision. Re-defining/correcting rules keeps the ID and creates a new revision
with a parent link. A RuleSet starts session-scoped; promotion is an explicit
host call. Promotion changes visibility, not semantic fingerprint or
provenance, and does not upgrade inferred assertions.

## Target Hunt: Maze

Define rules once, then admit multiple maps without changing the rule revision.
Pass this text as `oracle.ruleset.define.ruleset_dsl`:

```text
name: Target Hunt
description: Find a shortest orthogonal path
domain: target_hunt
movement: orthogonal
max_rows: 32
max_columns: 32
```

Admit an explicit problem through MCP:

```json
{"name":"oracle.problem.define","arguments":{"problem_dsl":"grid: .../.#./...\nstart: 0,0\ntarget: 2,2"}}
```

The equivalent model-facing DSL is:

```text
open! oracle.problem.define
problem_dsl: "grid: .../.#./...\nstart: 0,0\ntarget: 2,2"
```

Rows are separated by `/`; `.` is free and `#` blocked. Coordinates are
zero-based `row,column`. Maps must be rectangular and within the RuleSet's
1..32 row/column limits. Start and target must be free; they may coincide.
Admission returns the host problem ID, fingerprint, position and action
contract. Invalid input leaves the existing problem intact.

```text
open! oracle.action.verify
action_dsl: "open! target_hunt.move\ndirection: east"
```

```json
{"name":"oracle.action.verify","arguments":{"action_dsl":"open! target_hunt.move\ndirection: east"}}
```

Legal moves advance the persisted position. Illegal moves return `VIOLATED`
and preserve it. `oracle.goal.search` takes `{}` (DSL: `open! oracle.goal.search`),
returns a path from the current position, and does not execute its moves.
The host defaults to 2,048 expansions and depth 1,024. A verified path is
`SATISFIED`; exhausted reachable space is `VIOLATED`; a budget stop is `UNKNOWN`.
Proofs contain the initial state once and compact per-step positions/actions.
The search result ceiling is 256 KiB. Target Hunt admits no teaching/FlyDelta credit.

Rule definition, problem admission and verified moves use the `session_state`
tool risk class. MCP advertises `readOnlyHint=false`; inbound MCP policy must
allow writes. Normal native session operations require no filesystem-write
permission. Search preserves the problem position.

Guidance uses `runtime.adaptation.semi_oracle.outcome_guidance`, default `shadow`.
Target Hunt history has a separate V3 family, partitioned by scope,
RuleSet/revision, evaluator, action contract and budget. Categories use progress
toward the target and local free exits excluding the immediate return. BFS
distances never enter the adviser. Rotated/reflected copies and positions of
the same map/start/target share a fixture group. Proven-path observations are
positive; other branches remain unknown unless an actual leaf was proved.
A corridor allowing return is not a proven dead end. Algebra V1 remains readable.

The full model-free smoke uses two non-overlapping fixture families, each with
64 training and 32 held-out maps: mixed corridor/random mazes and recurring
barrier/detour mazes. Its `--quick` CTest profile retains both families and all
policy/bound variants, but uses 15 held-out maps (including historical
regressions 66 and 91) and two seeds to keep routine verification bounded. Full
mode performs one actual search at each expansion budget
16/64/256 per training map and freezes the resulting 384 search-evaluation
records. Fixture-group weighting prevents the three budget records from
counting as three independent maps. It compares ordinary ordering, seeded
random tie-breaking, shadow, exact experimental history-before-heuristic
ordering, and conservative exact history-after-heuristic ordering. Both exact
orders are measured with posterior mean and Thompson sampling where applicable;
the smoke also checks that `shadow` reproduces the reference proof and
expansion count. Focal bounds are 1.0/1.05/1.1/1.25 with deterministic
no-history, posterior-mean, and Thompson ordering; only stochastic Thompson
repeats eight seeds. Independent BFS validates every returned path and its
declared cost guarantee. A separate BFS truth pass labels branches
optimal/detour/unreachable and reports held-out sibling ranking and Brier score
without exposing BFS distance/regret to search features. JSONL can include
frontier snapshots for the historical budget-16 regressions (maps 66 and 91),
including selected node, `g/h/f`, posterior identity, available frontier,
remaining expansions, duplicate suppression and reopen counts. Reproduce with:

```sh
cmake --build build-agent-vulkan-cozo --target llama-agent-semi-oracle-target-hunt-smoke
build-agent-vulkan-cozo/bin/llama-agent-semi-oracle-target-hunt-smoke --quick
build-agent-vulkan-cozo/bin/llama-agent-semi-oracle-target-hunt-smoke --trace /tmp/target-hunt-full.jsonl
ctest --test-dir build-agent-vulkan-cozo -R 'semi-oracle' --output-on-failure
```

The full `--trace` invocation is intentionally separate from CTest because
the exhaustive trace can exceed hundreds of MiB and materially distort the
cost measurements. CTest runs `--quick` without trace output. The frontier
observer itself is covered by focused CTests; use a manual full trace run when
inspecting decisions, and treat any externally imposed timeout as an
incomplete run rather than as a result. Full mode can be run without `--trace`
for measurements; it is intentionally more expensive than routine CTest.

The frozen history retains all prediction inputs and source IDs, omitting
verbose diagnostic payloads from repeated parsing; the trace includes that
snapshot. Its projection timings describe this compact in-memory view, not
database loading. Search timing includes domain validation and proof building.

The smoke checks whether ordering reaches execution and emits paired
win/loss/unchanged and expansion deltas per held-out map, not just pooled seed
counts. Performance and budget success rates are measured results, not
acceptance assumptions. Exact A* always keeps minimum-f priority. Its default
historical order is `before_h` (`f → history score → h → ordinal`) among equal-f
nodes; the conservative `after_h` order is `f → h → history score → ordinal`.
The configured exact order and optional frontier observer reach both Target
Hunt and algebra; algebra always uses exact A*. Focal A* orders only entries
inside its host-selected `f <= w*f_min` set. Invalid host transitions and
path/frontier cost overflow fail the search instead of silently omitting a
branch and reporting exhaustive `VIOLATED`. A failed transition adviser leaves
that expansion in deterministic order with no partial historical scores. The
optional frontier observer performs its frontier scan only when enabled. No
GPU/model is required.

The optional `--trace` invocation writes JSONL only to the path explicitly
passed by the caller; CTest does not create or overwrite a trace file.

### Implementation status after the seam review

The current source replaces local sibling ranks with absolute posterior scores
in the frontier, including singleton successors. Scores use the state before
the action and are retained with the generated node. Algebra also uses these
scores within an exact minimum-`f` frontier. `shadow` retains the ordinary
executed order.

Target Hunt features are now `target_hunt_features_v3`, with suffix family
`target_hunt_search_suffix_v3`, history payload version 4 and evaluator
`target_hunt_astar_v3`. The wall mask, goal vector and movement vector are
transformed in the same coordinate frame. Coarse categories distinguish exit
degree and terminal/straight/corner/junction shape. Older payloads remain in
storage but do not contribute to this new feature/evaluator family.

Depth pruning can remove a cheaper route. If a goal is subsequently found,
reachability remains verified but optimality and Focal cost-bound proof flags
are conservatively false. The response reason explicitly reports this limit.
Exact search no longer scans the entire frontier merely to discard stale
entries before every expansion; selected candidates still reject stale paths.
Projection validation rejects category-dimension changes across fixtures and
non-finite accumulated weights. Accumulation and fingerprints are canonicalized
in projection format version 2. Invalid projection construction falls back to
deterministic search with a diagnostic reason. The fixture count reports the
union of eligible contributing groups, rather than the largest category count.

Target Hunt search evaluations now persist a separate, versioned
`target_hunt_branch_quality_v1` record beside the censored suffix observations.
Its reverse-BFS labels (`optimal`, `detour`, `unreachable`) are calculated by
the host after search and are not proof fields or model features. They are
scope-, RuleSet-, fixture-, feature-version- and truth-pass-bound. The adviser
validates the stored categories against current host feature functions, then
uses this family when it has eligible training groups; otherwise it falls back
to the older censored suffix family. Diagnostics identify which family was
used. The model-free smoke now also evaluates a projection reconstructed from
these production-persisted records, in addition to its independent full-map
BFS comparison.

Search-history projection caching is owned by each SemiOracle store instance,
not a process-global cache. It is bounded to 16 entries and a default estimated 16 MiB
including string/vector capacities and map-node overhead. The configurable
`runtime.adaptation.semi_oracle.outcome_guidance.projection_cache_bytes` defaults
to 16,777,216, accepts `0..268435456`, and zero disables retention. Active
searches can still hold their immutable projection outside the retained LRU.
Stores with a monotonic history watermark can look up before reading history;
Cozo reads a scope/RuleSet-specific persistent revision counter. Stores
without watermark support still read and fingerprint rows before reuse, while
preserving the current call's duplicate/conflict counters. Target state/action
feature pairs are cached during an evaluation so scoring, trace generation and
label validation do not repeatedly parse the same state/action pair.
The per-evaluation feature cache retains at most 4,096 state/action pairs and
clears on reaching that limit, preventing history spanning many maps from
retaining an unbounded collection of serialized states.

The 2026-10-20 source review additionally separates the store-local cache key
from the canonical validated-content fingerprint. Closing/reopening Cozo clears
its cache, and optional cache insertion failures retain the already built
projection. Complete history records are validated before either family is
aggregated, including branch state validity, legal action features and matching
fixture group. An invalid late branch cannot leave an earlier partial
contribution behind. Active-family counts and builder identity now describe the
projection actually used, and decision lineage includes the branch projection.
Cozo also retains the separate branch payload and applied exact/Focal policy,
matching the in-memory payload; evaluation appends on one store instance are
serialized. Legacy retry comparisons recover additive fields from stored
proof/diagnostic data where possible; unavailable policy provenance is not
invented. The focused Cozo and SemiOracle tests passed in the preceding
verification sweep. The subsequent algebra-policy and fail-closed search
corrections described above have not yet been built or run.

The subsequent integration correction adds the persistent
`agent_semi_oracle_history_revisions` relation with an atomic initial backfill.
Each new evaluation uses `ensure_not`/`insert` and advances its RuleSet counter
in the same Cozo transaction; retries cannot replace an existing payload or
increment its counter twice. The counter is read by its composite key rather

and matching history rows in one transaction. Stores without that query use a
bounded revision-before/after retry; unstable snapshots fall back explicitly.
See [Cozo transaction semantics](https://docs.cozodb.org/en/latest/stored.html).

Integration regression sources now cover shared projection reuse, unchanged

## Historical ordering for algebra search

`oracle.goal.search` also consumes the shared posterior math in
`common/agent/prediction/outcome-guidance.*` through the SemiOracle-specific
`semi-oracle-outcome-guidance.*` adapter. The tool remains argument-free;
the daemon supplies the policy and reads the existing evaluation store. A
bounded store-owned LRU reuses immutable grouped projections by their full
source/context fingerprint (maximum 16 entries); current-fixture exclusion is
applied after lookup. Stores without a revision watermark use the fingerprint
of the rows returned by the store, so changed history invalidates the cache.
Configure it independently of FlyDelta:

```json
{
  "runtime": {
    "adaptation": {
      "semi_oracle": {
        "search": {
          "algorithm": "exact",
          "suboptimality_bound": 1.0
        },
        "outcome_guidance": {
          "mode": "shadow",
          "seed": 0,
          "max_history_evaluations": 128,
          "sampling_policy": "posterior_sampling"
        }
      }
    }
  }
}
```

`off` skips history reads and automatic history capture. The default `shadow`
records posterior predictions and hypothetical orders while preserving the
existing successor order. `experimental` applies host-generated legal
successor/frontier guidance. `sampling_policy` accepts `posterior_sampling` or
`posterior_mean`; candidates sharing a category share one Thompson draw per
decision, seeded from decision and category identity rather than candidate
iteration order. Exact A* preserves minimum `f=g+h`; history only orders nodes
within the same `f` frontier. A cold start without matching action history
preserves the original order. Changing these configuration values requires
daemon restart. `seed` is a non-negative integer;
`max_history_evaluations` is bounded to 1..1024.

Search policy is separately host-controlled under
`runtime.adaptation.semi_oracle.search`: `algorithm` is `exact` (default) or
`focal`; `suboptimality_bound` is finite in `1.0..2.0`, and exact requires
`1.0`. Focal A* considers only nodes with `f <= bound * f_min`, then uses
deterministic or historical ordering within that set. The model cannot set the
bound. A successful proof reports `suboptimality_bound_proven`; it must not be
read as `optimality_proven` when the bound exceeds one. Algebra remains exact
regardless of the configured Target Hunt policy. The result's `search_policy`
reports the applied algorithm, bound, and proof flags even for `UNKNOWN`.

The algebra suffix family has its own vocabulary: a discovered, verified goal
suffix; a proven leaf with no successors; or an unresolved suffix. A discovered
path labels its incoming actions as goal-reaching. A node is a dead end only
after it has been expanded with no outgoing transitions. Unexpanded siblings,
depth-limited nodes and budget stops remain unknown. Unknown mass updates only
the Beta model for classification within the search budget, not the two
Dirichlet categories. These are coarse statistics by rewrite primitive under
the observed search policy and budget, not a learned state-value function.
Target Hunt uses a distinct `target_hunt_search_suffix_v3` family and
versioned, symmetry-normalized local features. It backs off from fine local
wall/goal/action patterns to Manhattan progress and successor degree unless at
least eight independent fixture groups support the fine category. This suffix
family remains censored search history; it is distinct from the model-free
smoke's BFS-derived branch labels (`optimal`, `detour`, `unreachable`). BFS
regret is a truth label, never a guidance feature.

Each initial equation defines a fixture group, and each group contributes at
most one unit of weight per action category across repeated searches. The
current fixture is excluded from its own history. Exact host/project/session
scope, RuleSet ID/revision, semantic and action-contract fingerprints, evaluator
revision, goal, budget and any explicit host action order must match. Inferred
rules provide no historical
guidance or new history observations. Model identity is not a partition here:
the search and its arithmetic are deterministic host operations.

At the start of each call the adapter freezes a bounded evaluation view,
sorted by evaluation ID; this order does not claim registration chronology or
recency. A SHA-256 fingerprint records the compatible history projection.
Both the in-memory and Cozo implementations persist the additive
`search_guidance_json` field in the existing evaluation record; old records
remain readable and have no historical observations. No new store is required.
History read failure, adviser exceptions or an invalid permutation retain
the normal search order and report a fallback. Completed evaluation storage
continues through the existing tool service.

MCP `oracle.goal.search` publishes a compact `guidance` summary in its
canonical result. The MCP `outputSchema` describes the common native success
payload (`ok`, `result`, optional summary/references), so this summary is at
`structuredContent.result.guidance`. Full diagnostics are saved with the evaluation and
logged as `[semi-oracle] outcome_guidance` when `agent_trace` is enabled:
history fingerprint and source evaluation references, accepted/rejected records,
duplicate/conflict counts, group counts, predictions and approximate marginal intervals,
proposed order, executed order and fallback. Up to 128 expansion decisions
are retained per call; further decisions are explicitly counted as omitted.
The shared read-only `prediction.predict` tool has an explicit
`family="target_hunt"` adapter for host-verified Target Hunt branch-quality
records under the active session RuleSet; `family="flydelta"` remains a
separate intervention-history adapter. The posterior core is shared, but the
outcome vocabularies and stores are not mixed. The tool accepts neither model-
supplied features nor training rows. Placement minimax still computes exact
adversarial values without this A* ordering adapter.
The tool uses the regular `prediction` routing family and read-only MCP
execution path. The `family` argument selects the prediction domain, not a
tool family. The previous tool name `outcome.predict` is removed.

## Authority and FlyDelta

Rule assertions retain `declared`, `verified` or `inferred` provenance. A
deterministic evaluator can still be applying an inferred or incorrect rule;
therefore evaluator determinism alone is not sufficient for training credit.
Only a same-revision contrast with a host-proved `VIOLATED` baseline and
`SATISFIED` candidate, no inferred assertions, and non-empty proof/counterexample
can be converted by `common_semi_oracle_make_teaching_relation` into the
existing teaching-relation contract with source `semi_oracle_preference`—not
`user_taught_concept`. It binds the session to the RuleSet revision, initial
state fingerprint, evaluator revision and action-contract fingerprint.
Revision changes must not reuse prior evidence without an explicit
compatibility check. `UNKNOWN`, exhausted budgets and inferred-only rule sets
remain diagnostic; they are not FlyDelta or training admission.

The bridge API creates the existing teaching-relation type; it does not
introduce a second capture/training store. The daemon persists an immutable
interaction record for a complete placement-game contrast, then its dedicated
provider materializes three session-scoped forced-context resources and sends
the ordinary relation through the existing evidence and capture ingress.

For strategic placement behavior, a legal-but-worse action is not an Oracle
violation. The host-only `rank_placements` service runs memoized minimax for
each legal action from the current player's perspective and persists the full
bounded result through the existing evaluation store. A FlyDelta preference
relation is eligible only when two distinct actions in the same state and
revision have complete, persisted proofs and the preferred outcome is strictly
better (`loss < draw < win`). This is a preference comparison, not a false
`VIOLATED` verdict. The relation remains session-scoped; it does not promote
the RuleSet or create a FlyDelta overlay by itself. A host producer still has
to resolve the observed, preferred and matched-control captures and present a
verified relation through the dedicated runtime seam; production capture and
admission gates then apply. Forced-context capture uses `n_predict=0` with a
host-owned terminal assistant continuation, so capture is deterministic while
free generation remains evaluation-only.

The daemon now attaches a `semi_oracle_preference` learning signal only when a
declared placement-game RuleSet has a complete minimax ranking and proves the
model's observed legal move strictly worse than another legal move. This is
stored as host-verified learning evidence with the tool observation. It is not
yet marked candidate-ready and does not itself enqueue FlyDelta capture: the
observed/preferred/control execution relation and activation capture still need
to pass through the ordinary relation provider and capture pipeline. Thus this
wiring is evidence ingress, not proof that nearline FlyDelta changes the
model's move selection.

## Offline SFT and leakage-safe splits

The same verified minimax action can become an SFT demonstration through
`common_semi_oracle_make_sft_candidate`, then enters the existing shared
learning corpus and trainer-job path. It is tagged
`host_verified_demonstration`, carries the persisted evaluation/action proof
reference, and requires a caller-provided redaction attestation and explicit
curator approval before corpus admission. This provenance path never invents
model occurrences or recoveries; those remain zero. In contrast,
`observed_model_behavior` candidates continue to require their normal
occurrence, verified-recovery and approval thresholds.

This admission is explicitly offline SFT only. The shared corpus builder opts
in to host-verified demonstrations for the SFT objective; DPO still requires
real chosen/rejected pairs, and default candidate qualification (including the
nearline auto-training trigger) rejects solver demonstrations. A solver proof
therefore cannot silently count as an observed model recovery or start online
training.

Position examples carry a `split_group_key` based on a canonical board under
the RuleSet's symmetry group (all eight symmetries for square boards and
dimension-preserving reflections for rectangular boards). The shared corpus
builder splits by this key when present, so rotated/reflected versions of one
position cannot straddle train, validation and test. RuleSet revision and
side-to-move are included in the group identity.

The current implementation exposes two distinct inputs for later comparison,
not two completed adaptation paths:

1. Runtime records host-verified evidence when minimax proves an observed
   model move strictly worse. It is not candidate-ready: matched preferred and
   control executions plus activation captures are not yet wired into the
   relation provider/capture pipeline.
2. Offline SFT can use curated solver demonstrations projected through the
   shared candidate, corpus, redaction and trainer-job contracts. This is a
   separate offline path and does not establish a FlyDelta effect.

The Qwen model smoke reports the observed move against minimax. When the
observed move is strictly worse, it also projects that same-state pair into
the shared offline DPO corpus and creates an ordinary DPO trainer job. The
smoke does not launch training, capture FlyDelta activations, activate or
claim an adapter. Adapter comparison remains a later operation over an
approved corpus and the same held-out symmetry groups. The smoke's DPO
projection is only corpus/trainer-job construction; it is not an adapter
training result.

## Strict minimax DPO pairs

For placement games, `common_semi_oracle_make_dpo_candidate` can project two
actions from the same persisted, complete minimax ranking into one ordinary
`common_training_candidate`. The chosen action must have a strictly better
minimax outcome than the rejected action. Equal-value moves are deliberately
not ordered. Both action proofs, the evaluation reference, RuleSet revision,
action-contract fingerprint and symmetry group are retained; the prompt and
redaction attestation still come from the host/curator. Inferred RuleSets are
rejected for both SFT and DPO admission.

The shared corpus builder accepts host-verified examples for SFT as before.
For DPO, host-verified pairs are rejected by default and require the explicit
offline-only `common_learning_corpus_policy::allow_host_verified_dpo_pairs`
opt-in. This flag only affects corpus construction; it does not relax nearline
candidate qualification or create observed model behavior. The DPO row uses
the chosen and rejected DSL actions from the pair, and its strict contrast
reference points back to the persisted minimax evaluation. This supports
curated corpus generation, not automatic adapter training, activation or
promotion.

SemiOracle teaching relations use the distinct `semi_oracle_preference`
evidence source. They must not be routed as `user_taught_concept`: the runtime
signal is a host-verifier result, not a statement that the user taught a
general concept. The runtime assembly now has a dedicated SemiOracle relation
provider seam and routes its accepted relations through the existing evidence,
teaching-material, capture, synthesis and FlyDelta search path. The daemon
configures the producer only after it has stored a same-session, same-revision
interaction with a verified contrast and matched control. It rejects incomplete
interaction records rather than inventing references.

The placement-game preference builder reloads its persisted minimax ranking
and verifies that both actions belong to the same state and RuleSet revision,
the preferred action is strictly better, and a matched control reference is
present. The general rejected/accepted relation builder supports correctness
contrasts such as algebra rewrites; it checks that both verifier records prove
the same initial state. Algebra relations establish equivalence only and do
not claim that one valid rewrite is strategically better.

The direct SemiOracle model smoke still tests rule/action inference and
offline DPO projection. It is not, by itself, evidence that a candidate has
survived capture, synthesis, direction/scale search, or held-out overlay
evaluation. For `linear_algebra`, bounded A* may suggest a path, but the host
uses only its first successor, renders it as a normal rewrite DSL action, and
requires the local evaluator to prove that action before materializing the
relation. The search's final solution is never treated as model output. A
separately verified, syntactically similar host control is mandatory; missing
repair or control material remains diagnostic only.

## Search levels

- `local`: verify one proposed placement or equation rewrite.
- `bounded`: placement games use deterministic minimax bounded by host depth
  and expansion limits. Linear equations use exact rational normalization to
  prove the unique solution; this is currently a bounded closed-form solver,
  not a general rewrite-tree search.
- `guided`: for placement games, host guidance changes move ordering only. The
  same legal transition model, search limits and verdict rules apply. Guidance
  is not a source of truth. V1 does not use a learned value model or MCTS.

Proof/counterexample data is emitted only for established results. A cutoff,
unsupported expression or invalid game state returns `UNKNOWN` (invalid DSL
shape is a tool validation failure).

## V1 constraints

`placement_game` supports boards up to 8×8, two alternating players, placing a
mark into an empty cell, a configurable contiguous win length and draw on a
full non-winning board. The first declared player starts. State validation
checks turn/count consistency and rejects simultaneous winners.

`linear_algebra` supports only variable `x`, integer constants, parentheses,
addition/subtraction, multiplication where at most one factor contains `x`,
and division by a non-zero rational scalar. It checks equivalence by exact
rational normalization. Unsupported/nonlinear expressions and arithmetic
overflow return `UNKNOWN`.
